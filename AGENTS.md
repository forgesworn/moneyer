# moneyer

An independent implementation of the LNURLcash (LUD-25) draft: a Lightning
mint that strikes bearer notes. Paying an invoice it issues mints a note
whose spend secret is chosen by the buyer, named to the mint only as a
hash. TypeScript, ESM-only, Node 24+, `node:http` and `node:sqlite` - no
web framework, no ORM, no third-party runtime crypto beyond `@noble/*` and
`@scure/base`. Amounts are millisatoshis throughout; a mint must never
touch fiat.

## Build & Test

| Command | Purpose |
|---------|---------|
| `npm install` | Install dependencies |

| `npm run typecheck` | Type-check without emitting |
| `npm run conform` | Run only the conformance test file |
| `npm run check` | Typecheck, test, build, web build and a dry-run `npm pack` - run before a release |

## Conventions

- British English in prose and comments.
- Amounts are millisatoshis everywhere; a mint must never touch fiat.
- ESM only; no CommonJS.
- No web framework or ORM - `node:http` and `node:sqlite` directly.
- Notes are stored by id, `sha256(k1)`; the store never holds a spend secret.

## Common Pitfalls

- Do not confuse the payment preimage with the note's spend secret: the
  preimage is settlement proof only, known to the funding source and route;
  the secret is the buyer's comment commitment, never generated by the mint.
- Mutations are atomic and compared by the note each `k1` spends: a Part 2
  note can have many valid `ck1` strings for one note.
- Melt is confirmed only on a confirmed payment; a clean failure report is
  not confirmation (hodl invoices) - see `runMelt` / `reconcilePendingMelts`.
- On a shared funding source, dedupe melts against the node's own payment
  history first; never confirm a melt against a payment this mint did not
  initiate.
